# RFC Size-8 Omega Proof Triage

Scope: original non-systematic RFC only.

The original GF(5) size-8 Omega scan was a live proof blocker:

```text
total profiles = 51480
complete-stride omegas = 24
complete-stride dim>=2 = 24
nonstride omegas = 51456
nonstride dim>=2 = 8534
max nonstride dimension = 4
```

The large-prime guard now classifies this red flag as a small-field degeneration for the current
seed-1 all-Omega replay. With `--omega-scan-fast-rank-only` over `GF(65537)`, seed `1`:

```text
total profiles = 51480
complete-stride dim>=2 = 24
nonstride dim>=2 = 0
max complete dimension = 2
max nonstride dimension = 1
status = ok
```

Thus, over the large-prime guard, the only size-8 profiles with dimension growth are the 24
complete-stride unions. The GF(5) scan still matters as a diagnostic warning, but it is no longer
evidence for production-relevant non-stride dimension growth unless the phenomenon reappears over
large fields or symbolic generic challenges.

The remaining proof obligation is therefore focused: prove or certify the complete-stride growth
case and show that its exact flags are charged by the two-layer recurrence.

## Object To Classify

For a row block:

```text
B_b = {4b, 4b+1, 4b+2, 4b+3}
```

and a size-8 output support:

```text
Omega subset [0..15],
|Omega| = 8,
```

the scan computes:

```text
K_Omega = { x supported on B_b : output outside Omega is zero }.
```

The old complete-stride target expected:

```text
dim K_Omega = 2
```

only when `Omega` is the union of two complete output stride classes. The scan found many
non-stride `Omega` with `dim K_Omega >= 2`.

The classifier must decide which of four buckets each such row belongs to if future large-field or
symbolic scans find non-stride `dim K_Omega >= 2` rows. For the current GF(5) red flag, the
large-prime guard places the non-stride rows in Bucket A.

## Bucket A: Small-Field Degeneracy

Classification:

```text
The row has dim K_Omega >= 2 over GF(5), but the extra dimension disappears over larger fields or
independent challenge samples.
```

This is harmless for the production `q=2^128` proof if the rank drop is caused by a low-degree
polynomial accident rather than an identity of the fold structure.

Required evidence:

```text
same (B_b, Omega) tested over GF(7), GF(11), and at least one large prime or symbolic sample;
dim K_Omega <= 1 for all non-GF(5) tests, or the rank-drop polynomial is shown nonzero.
```

Current evidence:

```text
GF(65537), seed 1, all size-8 Omega fast-rank scan:
  nonstride_dim_ge2 = 0 / 51456,
  max_nonstride_dim = 1.
```

This is enough to classify the current GF(5) non-stride explosion as small-field degeneration for
the seed-1 guard, pending broader prime/seed replay if the manager wants extra confidence.

Acceptance label:

```text
classification = small_field_degeneracy
proof_effect = ignore_for_large_q_except_as_constant/probability term
```

Not acceptable:

```text
calling the row small-field because it was first seen over GF(5) only.
```

## Bucket B: Contained-Support Overcount

Classification:

```text
K_Omega is large, but its vectors/lines have exact output support strictly contained in Omega.
```

Then the size-8 contained-support scan is overcounting. Exact-support inversion assigns the event
to smaller exact supports, where it must already be charged.

Required evidence:

For each bad `(B_b, Omega)`, compute the support spectrum of projective lines in `K_Omega`:

```text
exact output support of each line,
max exact support size,
number of exact-support Omega lines,
dimension of the subspace spanned by exact-support Omega lines.
```

The row is contained-overcount if:

```text
no projective line in K_Omega has exact output support Omega,
```

or, for a flag target:

```text
no canonical two-dimensional parent W or child flag has exact visible support Omega.
```

Acceptance label:

```text
classification = contained_support_overcount
proof_effect = handled_by_exact_support_inversion
```

Not acceptable:

```text
using dim K_Omega alone as a size-8 exact-support event.
```

## Bucket C: Duplicate Certificates Of Existing Exact Lines

Classification:

```text
The row contains exact lines/flags, but they are canonical duplicates of lines/flags already
generated by smaller supports or complete-stride supports.
```

This means non-stride `Omega` is only another certificate for an existing event.

Required evidence:

Canonicalize:

```text
each projective line ell <= K_Omega,
each parent W generated from the row,
each induced child flag L <= V.
```

Then compare against the canonical registry from:

```text
smaller exact supports,
complete-stride supports,
previously emitted targeted parent-W rows.
```

The row is a duplicate-certificate row if every exact line/flag maps to an existing canonical key.

Acceptance label:

```text
classification = duplicate_certificate
proof_effect = do_not_multiply_event_count
```

The classifier should still report:

```text
duplicate_certificate_count,
max_certificates_per_canonical_flag,
source bucket of the canonical event.
```

Not acceptable:

```text
counting multiple Omega supersets of the same line or flag as separate events.
```

## Bucket D: Real Extra q-Dimension

Classification:

```text
The row persists over large fields, survives exact-support inversion, and produces new canonical
lines/flags or multi-copy intersections above the generic flag/lift prediction.
```

This is a real proof obstruction.

Danger signals:

```text
1. exact-support Omega has a new two-dimensional K_Omega family not explained by previous buckets;
2. canonical parent-W or child-flag count exceeds the Gaussian Lift allowance by one q-dimension;
3. independent-copy intersections have v_excess >= 1 or l_excess >= 1;
4. the same profile recurs under paired compression or in multiple depth-4 blocks.
```

Acceptance label:

```text
classification = real_extra_q_dimension
proof_effect = new_recurrence_state_or_e72_fallback
```

This bucket does not automatically falsify `e=71`, but it invalidates the current two-layer proof
model until the extra state/charge is identified.

## Acceptance Criteria For Defusing The Blocker

The size-8 Omega blocker is defused for the current proof route by the large-prime guard if:

```text
large-prime nonstride_dim_ge2 = 0,
large-prime max_nonstride_dim <= 1,
complete-stride dim>=2 = 24,
max_complete_dim = 2.
```

This is exactly what the `GF(65537)`, seed `1`, fast-rank scan reports.

For a fully audited classification report, the older row-by-row criteria still apply:

```text
1. every small-field row is checked over GF(7), GF(11), and a large-prime/symbolic sample;
2. every contained-support row reports exact-support spectra proving it belongs to smaller buckets;
3. every duplicate-certificate row reports canonical keys and source buckets;
4. every complete-stride row still satisfies the direct-sum target:
     dim K_Omega = 2,
     K_Omega = ell_i direct_sum ell_j.
```

If these conditions hold, the scan becomes evidence that the current exact-support/flag counting
model is robust despite the scary contained-support dimension growth over GF(5).

Current manager-facing status:

```text
the broad GF(5) non-stride blocker is defused by the GF(65537) guard;
the remaining live obligation is complete-stride growth only.
```

## Remaining Complete-Stride Obligation

For each of the 24 complete-stride supports:

```text
Omega = C_i union C_j,
B_b fixed,
```

the proof/certificate path still needs:

```text
1. dim K_Omega = 2 generically;
2. K_Omega = ell_i direct_sum ell_j;
3. the two ordered flags ell_i <= K_Omega and ell_j <= K_Omega are canonical distinct events;
4. the total complete-stride support/flag count is 24 unmarked supports and 48 ordered flags;
5. parent-W and child-flag multiplicity stays within the Lift(t=2,tau=1,r0=1,r1=2) allowance;
6. independent-copy intersections of these exact flags obey the generic flag-intersection exponent
   unless they are paired-compression structure already charged recursively.
```

The large-prime Omega scan supports item `1` for the absence of non-stride competitors, but it does
not by itself prove the full complete-stride direct-sum and flag-lift obligations.

## Rejection Criteria

The proof route must treat the broad non-stride blocker as unresolved if a future large-prime or
symbolic replay finds:

```text
nonstride_dim_ge2 > 0
```

or if any claimed classification is labeled by assertion rather than canonical support/flag data.

The proof route must add new state or evaluate the `e=72` fallback if:

```text
real_extra_q_dimension_count > 0
```

and the extra canonical event persists beyond GF(5) and is not paired-compression structure already
charged by the recurrence.

One reusable extra q-dimension is a 128-bit effect at production `q=2^128`, larger than the current
`e=71` slack. It cannot be absorbed as a constant.

## Feedback For Implementation

If more audit evidence is desired, prioritize the classifier in this order:

```text
1. repeat the fast-rank all-Omega scan over GF(7), GF(11), and one additional large prime/seed;
2. only if nonstride_dim_ge2 reappears, classify those rows by exact support and canonical flags;
3. otherwise focus implementation effort on complete-stride direct-sum, lift, and intersection
   checks.
```

Do not run a broad production-size benchmark for this. The goal is classification of the proof
obstruction, not timing or a large sample.

## Manager Interpretation

The current combined scan result means:

```text
complete-stride-only dimension growth is false over GF(5),
but true in the GF(65537), seed 1, size-8 all-Omega guard.
```

The proof can proceed past the broad non-stride Omega blocker, while keeping GF(5) as a warning
about small-field artifacts. The proof cannot close until the remaining complete-stride growth case
is incorporated into the flag recurrence with exact support, canonical flag, lift, and intersection
counts.
